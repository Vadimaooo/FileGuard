# FileGuard 1.1 — Інструкція користувача

## Призначення

FileGuard перевіряє, чи змінився вміст файлів обраної папки відносно
збереженого еталона. Для кожного файлу обчислюється SHA-256. Інтерфейс,
повідомлення та звіти написані українською. Програма працює локально.

## Запуск

Для готової Windows-збірки:

1. Розпакуйте FileGuard-Windows.zip у папку, в якій дозволений запис.
2. Відкрийте FileGuard.exe подвійним натисканням. Python установлювати не потрібно.
3. Зберігайте папки data та reports разом із програмою: у них містяться
   локальні дані. Не запускайте програму безпосередньо з ZIP-архіву.

Для запуску вихідного коду потрібен Python 3.10+ та PySide6. Відкрийте
папку проєкту у Visual Studio Code та виконайте в терміналі:

```powershell
python -m pip install -r requirements.txt
python main.py
```

Поточну версію перевірено на Windows 11 x64, Python 3.13.2 / Qt 6.10.3.
Рекомендована роздільна здатність — від 1280 × 1024 за масштабу 100%.
Мінімальний розмір вікна — 1080 × 820 пікселів.
Зберігайте програму в доступній для запису папці, наприклад у власних документах.

## Перша перевірка

1. Натисніть «Обрати папку» та виберіть папку з файлами для контролю.
2. Укажіть, чи потрібно включати вкладені папки.
3. За потреби на вкладці «Налаштування» додайте правила виключення та
   натисніть «Застосувати виключення».
4. Натисніть «Створити еталон» і збережіть JSON. Створюйте еталон тоді,
   коли файли мають відомий правильний стан.
5. Перевірте кількість записів. Якщо доступна кнопка «Пропущені шляхи»,
   прочитайте причини: такі шляхи не отримали початкового хешу.
6. Натисніть «Перевірити цілісність». Програма повторно прочитає файли
   та порівняє хеші з еталоном.

Еталон — це перелік шляхів, розмірів, дат і хешів, а не копії вмісту.
Не змінюйте еталон після кожної підозрілої зміни: новий еталон приймає
поточний стан за початковий. Зберігайте еталон у довіреному місці та робіть
резервну копію окремо від папки контролю.

## Статуси

| Статус | Значення |
| --- | --- |
| Без змін | Поточний SHA-256 збігається з початковим. |
| Змінено | Хеш вмісту відрізняється від еталона. |
| Додано | Поточний файл відсутній в еталоні. |
| Видалено | Початковий файл не знайдено під час успішного обходу. |
| Помилка | Файл або шлях не вдалося достовірно порівняти. |

Шість карток показують загальну кількість записів та кількість кожного
статусу. Після перевірки загальна кількість включає видалені файли та
записи про помилки. Помилка папки може мати власний рядок і рядки її
неперевірених файлів.

Виберіть рядок і натисніть «Відомості», Enter або двічі натисніть рядок.
Відкриються розміри, початковий і поточний SHA-256 та пояснення.
«Помилки перевірки» показують причини недоступності шляхів.

Поки завантажено лише еталон, позначка «В еталоні» ще не підтверджує
незмінність. Кольорові результати з'являються після порівняння.

## Фільтр та виключення

Список над таблицею дозволяє обрати один статус або «Усі статуси».
Фільтр змінює лише видимі рядки. Картки й експорт завжди охоплюють весь результат.

Правила виключення вводяться по одному на рядок:

| Правило | Що виключає |
| --- | --- |
| *.tmp | Відповідні імена файлів або папок на будь-якій глибині. |
| .git | Компонент шляху .git разом із його вмістом. |
| cache/ | Папки cache та їхній вміст, але не звичайний файл cache. |
| logs/*.log | Відносні шляхи logs/*.log, включно з вкладеними компонентами. |

Регістр не враховується. Допускається до 100 правил, кожне до 256 символів.
Абсолютні шляхи, переходи .. і правила заперечення з ! не підтримуються.
Спочатку натисніть «Застосувати виключення»; незастосований текст не зберігається.

Правила й параметр вкладених папок записуються в новий еталон. Перевірка
завантаженого еталона використовує його власні параметри. Щоб змінити
охоплення, створіть новий еталон. JSON усередині папки контролю виключається
автоматично; службові підпапки data і reports виключаються при створенні
еталона папки програми.

## Історія та звіти

Кожна завершена перевірка зберігається в data/history.sqlite3. На вкладці
«Історія» показано останні 200 записів; старші записи не видаляються.
Виберіть запис і натисніть «Відкрити» або двічі натисніть рядок.
Збережений результат доступний навіть після переміщення вихідної папки;
відкриття історії не запускає повторне сканування.

Меню «Зберегти звіт» у головному вікні або перегляді історії пропонує:

- TXT: читабельний текст із підсумками, поясненнями та хешами всіх записів.
- CSV: таблицю UTF-8 із BOM і роздільником ; для відкриття в Excel.

Виберіть місце поза папкою контролю. Службова папка reports дозволена,
якщо її виключено в еталоні. Для CSV використовується початковий апостроф
у значеннях, схожих на формули, щоб табличний редактор читав їх як текст.
Підтвердження перезапису наявного файлу виконує системний діалог.

## Налаштування та закриття

Бічне меню перемикає сторінки «Перевірка», «Історія» та «Налаштування».
Вікно можна перетягувати за верхню вільну смугу, змінювати розмір за краї,
згортати, розгортати й закривати кнопками праворуч угорі. Подвійне натискання
верхньої вільної смуги розгортає або відновлює вікно.

«Зберегти налаштування» записує останню папку, параметр вкладених папок,
застосовані виключення, фільтр і розмір вікна в data/settings.json.
Ці самі параметри автоматично зберігаються під час звичайного закриття.
Після запуску папка відновлюється як вибір, але еталон потрібно завантажити
кнопкою «Завантажити еталон». Сканування автоматично не починається.

Інтерфейс використовує світлий непрозорий фон та округлені картки й кнопки.
Еталони та історія версії 1.0 сумісні з версією 1.1.

Під час тривалої операції доступна кнопка «Скасувати». Закриття вікна
спочатку запитує скасування, очікує завершення потоку та прибирає
тимчасові файли. Дочекайтеся закриття вікна; примусове завершення процесу
не гарантує збереження останніх параметрів.

Для резервної копії локальних даних закрийте програму та скопіюйте папку data.
Копіювання лише exe не переносить історію та налаштування. При перенесенні
папки з контрольованими файлами старий JSON усе ще містить попередній
абсолютний шлях; оберіть нове розташування та створіть еталон там.

## Типові проблеми

| Ситуація | Дія |
| --- | --- |
| Папку переміщено або видалено | Оберіть доступну папку. Відкрити давню історію можна без неї. |
| Файл зайнятий або недоступний | Перевірте причину у «Відомостях», закрийте редактор файлу й повторіть перевірку. |
| Файл змінюється під час читання | Завершіть його редагування та повторіть операцію. |
| Пошкоджений JSON еталона | Завантажте довірену резервну копію. Попередній еталон у вікні зберігається. |
| Помилка запису історії | Поточний результат залишається у вікні; експортуйте його та перевірте місце/доступ до data. |
| Пошкоджені налаштування | Повідомлення пояснить помилку. Файл зберігається до застосування нових параметрів або явного збереження. |
| Не вдається зберегти дані | Перенесіть програму до папки з правом запису та перевірте вільне місце. |
| Після фільтра таблиця порожня | Оберіть «Усі статуси»; загальні картки містять результат усієї перевірки. |

## Межі можливостей

Перевірка запускається вручну; це не постійне спостереження за файловою системою.
Порівнюється вміст, а не права доступу чи власник. Зміна лише дати без зміни
байтів не утворює статус «Змінено». Перейменування показується як видалення
старого шляху та додавання нового. Шляхи порівнюються без урахування регістру
відповідно до звичайної роботи Windows.

Символічні посилання, junction і спеціальні файли пропускаються з поясненням.
Еталон обмежений 64 МіБ, один знімок історії — 128 МіБ, налаштування — 1 МіБ.
Обсяг історії зростає з кількістю перевірок.

SHA-256 допомагає виявити відмінність, але еталон не має цифрового підпису.
Програма не визначає автора зміни, не перевіряє файли на віруси й не відновлює
видалений вміст. Сканування всієї папки не є миттєвим знімком: для
відтворюваної перевірки дочекайтеся завершення запису в контрольовані файли.

## Демонстрація для захисту

1. Скопіюйте demo_files до окремої робочої папки та створіть її еталон.
2. Виконайте перевірку: три файли повинні мати статус «Без змін».
3. У тестовій копії змініть Приклад.txt, видаліть Нотатки.txt і додайте новий файл.
4. Повторіть перевірку: по одному «Змінено», «Видалено», «Додано» та
   «Без змін» для вкладеного JSON.
5. Покажіть хеші зміненого файлу, фільтр, історію та експорт CSV.
6. Перезапустіть програму та відкрийте збережений результат з історії.
