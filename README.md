# FileGuard — Контроль цілісності файлів

Курсовий проєкт з дисципліни «Безпека та захист програм і даних».

## Поточний стан: FileGuard 1.1 — інтерфейс PySide6

Світлий інтерфейс Qt Widgets: бічна навігація, округлені картки й кнопки,
векторні значки, перемикачі та кольорові позначки статусів.
У версії 1.1.1 використовується єдиний світлий непрозорий фон.
[Пояснення структури Qt](docs/INTERFACE.md) призначене для знайомства з кодом.

[Інструкція користувача](docs/USER_GUIDE.md) містить порядок роботи,
пояснення статусів, типові помилки та сценарій демонстрації.
[Протокол перевірки](docs/TESTING.md) описує перевірені сценарії та межі перевірки.

Реалізовано інтерфейс MVC, створення та завантаження JSON-еталона SHA-256,
повторне хешування і порівняння файлів. Таблиця показує текстові та кольорові
статуси «Без змін», «Змінено», «Додано», «Видалено», «Помилка». Шість карток
показують загальну кількість записів та кількість кожного статусу. Доступні
дата й тривалість перевірки, початковий і поточний хеші, пояснення помилок.

Сканування та робота з JSON виконуються у фоновому потоці. Операції можна
скасувати; велика таблиця відображається через модель Qt без віджета для кожного рядка. Сам еталон перевірка
не змінює. Додано фільтрацію за статусом, правила виключення та постійну історію.
Реалізовано збереження налаштувань та експорт TXT/CSV.

Налаштування зберігаються у `data/settings.json`: остання папка, параметр
вкладених папок, застосовані виключення, фільтр статусу та розмір вікна.
Запис виконується кнопкою «Зберегти налаштування» або під час закриття.
Незастосований текст правил спочатку потрібно підтвердити кнопкою
«Застосувати виключення». Після запуску параметри відновлюються без
автоматичного сканування чи завантаження еталона. Збережений шлях може
вказувати на переміщену папку; для нового сканування слід обрати доступну.
Пошкоджені налаштування викликають повідомлення й залишаються недоторканими
при звичайному закритті. Застосування нових параметрів або явне збереження
дозволяє замінити їх коректним файлом. Максимальний розмір налаштувань — 1 МіБ.

Меню «Зберегти звіт» пропонує TXT або CSV для поточного результату та
результатів з історії. Експортується повний результат незалежно від фільтра.
TXT містить підсумки, причини та хеші. CSV використовує UTF-8 із BOM і роздільник
`;` для зручного відкриття в Excel; текстові значення, схожі на формули,
отримують початковий апостроф. Порожня перевірка зберігає рядок підсумків
без імені файлу. Запис атомарний: скасування чи помилка не псують старий звіт.
Збереження поверх файлів папки перевірки заборонене; дозволена службова
папка звітів, якщо вона виключена зі сканування.

Історія зберігається у `data/history.sqlite3` транзакціями SQLite. Вкладка
«Історія» показує останні 200 записів; старші записи не видаляються. Кнопки
«Оновити» та «Відкрити» читають збережені результати. Окреме вікно показує
повний звіт із хешами без повторного читання вихідних файлів і без заміни
поточного еталона. Помилка сховища не приховує успішний результат перевірки.
Збереження одного знімка історії обмежене 128 МіБ.

На вкладці «Налаштування» можна вказати до 100 правил, по одному на рядок,
та натиснути «Застосувати виключення». `*.tmp` виключає відповідні імена
файлів на будь-якій глибині; `.git` або `__pycache__` виключає компонент
шляху разом із вмістом; `cache/` стосується лише папок; `logs/*.log`
зіставляється з відносним шляхом. Регістр не враховується, `*` у повному
шляху може охоплювати вкладені компоненти. Нові правила застосовуються
лише до нового еталона. Фільтр таблиці не змінює загальні лічильники.
Службові підпапки `data/` і `reports/` автоматично виключаються під час
створення еталона папки проєкту, щоб запис історії не змінював його охоплення.

До порівняння «Усього» означає кількість файлів еталона, решта показників
невизначені. Після порівняння «Усього» дорівнює сумі п'яти статусів і враховує
видалені файли та записи про недоступні шляхи. Помилка папки може утворювати
окремий запис та записи її неперевірених файлів. «В еталоні» позначає лише
збережений запис, а не підтвердження незмінності файлу.

## Запуск у Visual Studio Code

Потрібен Python 3.10+ та залежності з `requirements.txt`.
Перевірено на Windows із Python 3.13.2 та PySide6/Qt 6.10.3.

1. Відкрити у VS Code папку `FileGuard`, у якій міститься `main.py`.
2. Відкрити термінал через меню **Terminal → New Terminal**.
3. Виконати:

```powershell
python -m pip install -r requirements.txt
python main.py
```

Рекомендовано окреме віртуальне середовище. У цьому робочому просторі
воно розміщене на диску F через обмежене місце на E:

```powershell
F:\FileGuard-runtime\Scripts\python.exe main.py
```

У VS Code потрібно обрати цей інтерпретатор через **Python: Select Interpreter**.

Можна запускати `main.py` з іншої робочої папки, указавши повний шлях.
Якщо команда `python` недоступна, спробувати `py -3 main.py`.

## Готова Windows-збірка

Локальний результат збирання: `dist/FileGuard/FileGuard.exe` та
`dist/FileGuard-Windows.zip`. Розпакувати архів до доступної для запису папки
та запустити exe. Python на цільовому комп'ютері не потрібен.
Історія, налаштування й еталони розміщуються в `data/` поряд з exe;
типове місце звітів — `reports/`. Самі файли збірки не включаються до Git.

Для повторної збірки у Windows із Python 3.13 x64:

```powershell
python -m pip install -r requirements-build.txt
python tools/build_windows.py
```

Щоб розмістити проміжні файли на іншому диску:

```powershell
python tools/build_windows.py --work-dir F:\FileGuard-build
```

Скрипт використовує PyInstaller 6.22.3 у режимі одного exe без консольного вікна.
До ZIP включаються exe, інструкція, демонстраційні файли, порожні папки даних
і перелік SHA-256; локальна історія, налаштування та особисті еталони не додаються.
У збірці шляхи даних визначаються через `sys.executable`, відповідно до
[документації PyInstaller](https://pyinstaller.org/en/v6.12.0/runtime-information.html),
щоб не записувати їх до тимчасової папки розпакування.

## Архітектура: MVC та сервіси

```text
main.py                         Створення та поєднання компонентів
app/paths.py                    Сталі шляхи вихідного коду та exe
app/models.py                   Стан, еталон, статуси та завершені результати
app/controllers/app_controller.py Оброблення дій, оновлення стану
app/views/main_window.py        Вікно, віджети, системні діалоги
app/views/theme.qss             Кольори, скруглення та стилі
app/views/widgets.py            Перемикач, картка й рамка вікна
app/views/icons.py              Спільні векторні значки
app/views/table_models.py       Адаптер даних таблиці та позначки статусів
app/views/saved_result_window.py Перегляд та експорт збереженої перевірки
app/services/directory_service.py Перевірка папки у файловій системі
app/services/integrity_service.py Спільне сканування SHA-256 та порівняння
app/services/baseline_storage.py JSON, перевірка формату, атомарний запис
app/services/exclusions.py      Правила виключення шляхів
app/services/history_storage.py Постійна історія SQLite
app/services/report_codec.py    Перевірка знімків історії та текст звіту
app/services/report_service.py  Експорт повних звітів TXT/CSV
app/services/settings_storage.py Збереження й відновлення параметрів
app/services/atomic_file.py      Спільний атомарний запис текстових файлів
data/                           Еталони, історія та налаштування
reports/                        Експортовані звіти
demo_files/                     Безпечні приклади для демонстрації
tests/                          Перевірки сервісів, контролера та вікна
tools/build_windows.py          Створення exe, ZIP і контрольних сум
docs/                           Інструкція користувача та протокол перевірки
```

Напрямок взаємодії: **дія у View → Controller → Service → Model → оновлення View**.
Контролер залежить від контракту `AppView`, тому його можна перевіряти без вікна.
Сервіс не імпортує Qt. Представлення не працює з файлами перевірки напряму.
Коментарі та пояснювальні рядки документації в коді написано українською.

## Контроль версій

Репозиторій: [Vadimaooo/FileGuard](https://github.com/Vadimaooo/FileGuard).
Основна гілка: `main`.

Після завершення кожного етапу:

1. Перевірити програму та актуальність цієї інструкції.
2. Переглянути зміни через `git diff` і перелік файлів через `git status`.
3. Зберегти завершені зміни окремим комітом із коротким описом українською.
4. Надіслати коміт до GitHub командою `git push`.

Дані з `data/`, звіти з `reports/`, локальні налаштування редактора та службові
файли Python не включаються до репозиторію. Для відтворення структури папок
`data/` і `reports/` зберігаються лише порожні файли `.gitkeep`.

## Як створити та завантажити еталон

1. Запустити програму та натиснути «Обрати папку».
2. Вибрати `demo_files`; залишити ввімкненим параметр вкладених папок.
3. Натиснути «Створити еталон» та зберегти JSON, наприклад у `data/`.
4. Перевірити три записи в таблиці, дату створення та повідомлення про завершення.
5. Закрити програму, запустити її знову та натиснути «Завантажити еталон».
6. Вибрати збережений JSON: папка, параметри та список файлів повинні відновитися.
7. Створити інший еталон без вкладених папок: у ньому буде два файли.

Для великої папки під час сканування доступна кнопка «Скасувати». Вибір папки
та параметри тимчасово заблоковані, щоб не змінювати завдання посеред виконання.
Закриття вікна під час операції спочатку запитує її скасування, прибирає
тимчасовий файл та завершує роботу. Перед перезаписом наявного JSON системний
діалог запитує підтвердження. Помилка завантаження не скидає поточний еталон.

## Як перевірити цілісність

1. Для експерименту скопіювати `demo_files` до окремої тестової папки.
2. Обрати цю папку, створити еталон і зберегти JSON, наприклад у `data/`.
3. Натиснути «Перевірити цілісність»: усі три файли мають статус «Без змін».
4. Змінити вміст `Приклад.txt`, додати новий текстовий файл та видалити
   `Нотатки.txt` лише з тестової копії.
5. Знову натиснути «Перевірити цілісність»: мають бути по одному запису
   «Змінено», «Додано», «Видалено» та один «Без змін» для вкладеного JSON.
6. Вибрати рядок і натиснути «Відомості» або двічі натиснути рядок/натиснути
   Enter. Вікно показує статус, пояснення, розміри та SHA-256 обох станів.
7. За наявності помилок натиснути «Помилки перевірки» для перегляду причин.

Кожна перевірка використовує параметри та виключення завантаженого еталона.
Прапорець вкладених папок налаштовує створення нового еталона і не скорочує
охоплення вже наявного. Вибір іншої папки скидає непридатний для неї еталон.
Після перезапуску для нової перевірки потрібно завантажити JSON; попередні
результати доступні на вкладці «Історія». Успішне створення або завантаження
еталона скидає поточну таблицю результатів, але не видаляє історію.

Порівнюється SHA-256 вмісту: однакові розмір та дата не приховують зміну
вмісту; зміна лише дати без зміни байтів не означає «Змінено». Перейменування
файлу на інший шлях відображається як видалення старого та додавання нового.
Шляхи зіставляються без урахування регістру відповідно до звичайної роботи Windows.

Помилки читання не вважаються видаленням. Помилка обходу папки поширюється
на її неперевірені дочірні шляхи. Якщо початкового хешу немає через неповний
еталон, програма показує «Помилка», навіть коли доступ до файлу відновлено.
Успішно прочитані файли з відомими початковими хешами порівнюються звичайно.
Недоступність кореневої папки завершує операцію помилкою; усі файли не
перетворюються на видалені. Скасування або збій не замінюють попередній
завершений результат неповними даними; під час повторної операції таблиця
позначена як попередні результати. Час завершення показаний під таблицею.

## Що містить еталон

Формат версії 2 містить назву застосунку, алгоритм, час створення з часовим
поясом, абсолютний шлях до кореневої папки, параметр вкладених папок,
масиви `files`, `issues`, `excluded_paths` та `exclusion_patterns`. Старі
еталони версії 1 читаються без нових правил. Для кожного файлу зберігаються
відносний шлях із роздільником `/`, SHA-256, розмір у байтах та час зміни
в наносекундах від початку Unix-епохи.

Час створення відображається в локальному часовому поясі. Вміст файлів не
копіюється: еталон не замінює резервну копію і має зберігатися в довіреному місці.
Завантаження читає збережені метадані без повторного сканування, тому можливе
навіть тоді, коли вихідну папку переміщено. Для сканування потрібна доступна папка.

JSON перевіряється до застосування: версія та алгоритм, типи полів, хеші,
унікальність і коректність відносних шляхів. Неповний або пошкоджений файл
відхиляється. Максимальний розмір JSON — 64 МіБ.

Якщо JSON розміщено всередині вихідної папки, його шлях автоматично виключається
зі сканування і зберігається в `excluded_paths`. Символічні посилання та junction
не обходяться. Недоступні файли, спеціальні файли та файли, змінені під час
читання, не включаються до знімка; причини доступні через кнопку
«Пропущені шляхи». Повний список причин зберігається у JSON. Еталон із такими
записами охоплює лише успішно прочитані файли.

Запис виконується через тимчасовий файл і атомарну заміну. Скасування до
заміни або помилка запису не пошкоджують попередній файл еталона.

## Перевірки

Автоматизовані перевірки хешування, JSON, п'яти статусів, контролера,
скасування, неповного обходу, реального блокування файлу Windows,
виключень, історії SQLite, TXT/CSV та налаштувань:

```powershell
python -m unittest discover -s tests -v
```

Перевірка справжнього вікна, порівняння, лічильників, кольорів, відомостей,
помилок та великої таблиці потребує графічного сеансу Windows:

```powershell
python tests/smoke_ui.py
python tests/smoke_persistence_ui.py
```

## Завершені етапи

1. Каркас Python, інтерфейс і MVC (початково tkinter).
2. Створення та завантаження JSON-еталона SHA-256.
3. Порівняння з еталоном, п'ять статусів і пояснення.
4. Виключення, фільтр, історія, TXT/CSV та налаштування.
5. Наскрізна перевірка, інструкція й переносна Windows-збірка.
6. Оновлення оформлення на PySide6/Qt зі збереженням форматів даних.

Оформлення пояснювальної записки курсового проєкту виконується окремо.
