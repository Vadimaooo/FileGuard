# FileGuard — Контроль цілісності файлів

Курсовий проєкт з дисципліни «Безпека та захист програм і даних».

## Поточний стан: етап 2

Реалізовано інтерфейс MVC, вибір папки, створення еталона SHA-256, збереження
та перевірку JSON, завантаження еталона після перезапуску. Показуються дата
створення, параметр вкладених папок, кількість і список збережених файлів.
Сканування, читання та запис JSON виконуються у фоновому потоці; операцію
можна скасувати. Рядки великої таблиці додаються порціями.

Порівняння з еталоном, історія перевірок, користувацькі виключення та експорт
ще не реалізовані. Їхні кнопки неактивні. Показник «Усього» стосується файлів
еталона, решта лічильників показують тире. Статус «В еталоні» означає наявність
запису в еталоні, а не підтвердження незмінності файлу.

## Запуск у Visual Studio Code

Потрібен Python 3.10 або новіший із tkinter. Зовнішні пакети не потрібні.
Перевірено на Windows із Python 3.13.2 та Tk 8.6.

1. Відкрити у VS Code папку `FileGuard`, у якій міститься `main.py`.
2. Відкрити термінал через меню **Terminal → New Terminal**.
3. Виконати:

```powershell
python main.py
```

Можна запускати `main.py` з іншої робочої папки, указавши повний шлях.
Якщо команда `python` недоступна, спробувати `py -3 main.py`.

## Архітектура: MVC та сервіси

```text
main.py                         Створення та поєднання компонентів
app/models.py                   Стан застосунку без залежності від tkinter
app/controllers/app_controller.py Оброблення дій, оновлення стану
app/views/main_window.py        Вікно, віджети, системні діалоги
app/services/directory_service.py Перевірка папки у файловій системі
app/services/integrity_service.py Потокове читання та SHA-256
app/services/baseline_storage.py JSON, перевірка формату, атомарний запис
data/                           Рекомендоване місце для еталонів
reports/                        Місце для майбутніх звітів
demo_files/                     Безпечні приклади для демонстрації
tests/                          Перевірки сервісів, контролера та вікна
```

Напрямок взаємодії: **дія у View → Controller → Service → Model → оновлення View**.
Контролер залежить від контракту `AppView`, тому його можна перевіряти без вікна.
Сервіс не імпортує tkinter. Представлення не працює з файлами перевірки напряму.
Коментарі та пояснювальні рядки документації в коді написано українською.

## Контроль версій

Репозиторій: [Vadimaooo/FileGuard](https://github.com/Vadimaooo/FileGuard).
Основна гілка: `main`.

Після завершення кожного етапу:

1. Перевірити програму та актуальність цієї інструкції.
2. Переглянути зміни через `git diff` і перелік файлів через `git status`.
3. Зберегти завершені зміни окремим комітом із коротким описом українською.
4. Надіслати коміт до GitHub командою `git push`.

Дані з `data/`, звіти з `reports/`, локальні налаштування редактора та службові
файли Python не включаються до репозиторію. Для відтворення структури папок
`data/` і `reports/` зберігаються лише порожні файли `.gitkeep`.

## Як створити та завантажити еталон

1. Запустити програму та натиснути «Обрати папку».
2. Вибрати `demo_files`; залишити ввімкненим параметр вкладених папок.
3. Натиснути «Створити еталон» та зберегти JSON, наприклад у `data/`.
4. Перевірити три записи в таблиці, дату створення та повідомлення про завершення.
5. Закрити програму, запустити її знову та натиснути «Завантажити еталон».
6. Вибрати збережений JSON: папка, параметри та список файлів повинні відновитися.
7. Створити інший еталон без вкладених папок: у ньому буде два файли.

Для великої папки під час сканування доступна кнопка «Скасувати». Вибір папки
та параметри тимчасово заблоковані, щоб не змінювати завдання посеред виконання.
Закриття вікна під час операції спочатку запитує її скасування, прибирає
тимчасовий файл та завершує роботу. Перед перезаписом наявного JSON системний
діалог запитує підтвердження. Помилка завантаження не скидає поточний еталон.

## Що містить еталон

Формат версії 1 містить назву застосунку, алгоритм, час створення з часовим
поясом, абсолютний шлях до кореневої папки, параметр вкладених папок,
масиви `files`, `issues` та `excluded_paths`. Для кожного файлу зберігаються
відносний шлях із роздільником `/`, SHA-256, розмір у байтах та час зміни
в наносекундах від початку Unix-епохи.

Час створення відображається в локальному часовому поясі. Вміст файлів не
копіюється: еталон не замінює резервну копію і має зберігатися в довіреному місці.
Завантаження читає збережені метадані без повторного сканування, тому можливе
навіть тоді, коли вихідну папку переміщено. Для сканування потрібна доступна папка.

JSON перевіряється до застосування: версія та алгоритм, типи полів, хеші,
унікальність і коректність відносних шляхів. Неповний або пошкоджений файл
відхиляється. Максимальний розмір JSON — 64 МіБ.

Якщо JSON розміщено всередині вихідної папки, його шлях автоматично виключається
зі сканування і зберігається в `excluded_paths`. Символічні посилання та junction
не обходяться. Недоступні файли, спеціальні файли та файли, змінені під час
читання, не включаються до знімка; причини доступні через кнопку
«Пропущені шляхи». Повний список причин зберігається у JSON. Еталон із такими
записами охоплює лише успішно прочитані файли.

Запис виконується через тимчасовий файл і атомарну заміну. Скасування до
заміни або помилка запису не пошкоджують попередній файл еталона.

## Перевірки

Автоматизовані перевірки хешування, JSON, контролера, скасування та помилок:

```powershell
python -m unittest discover -s tests -v
```

Перевірка справжнього вікна, створення, повторного завантаження та великої
таблиці потребує графічного сеансу Windows:

```powershell
python tests/smoke_ui.py
```
